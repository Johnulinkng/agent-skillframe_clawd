6.1 新闻预处理
- 模型类型：LLM
- 模型：Qwen3-8b-vl（视计算资源来权衡是否用8b或以上的模型）
- 平台：runpod租赁的服务器部署
- 模型输入（任意语言）
  - 新闻标题
  - 新闻媒体名
  - 新闻正文
  - 新闻发布时间
  - 图片
- 模型输出（英语）
  - 新增新闻的一到两句白话总结，放到新闻卡片的标题下方
  - 语言类型（zh/en/按需要增加....）
  - 文章利好/空的token/预测市场标的（1或多个）
  - 对最相关的一个代币是利好还是利空（用1-100分）
  - 最相关利好/利空的1～5个标的
  - 对各个利好/空的标的的置信分数 (-100,100)，例如80表示极大利好，-10表示微利空，
  - 对利好的标的在新闻详情页里面“相关代币”的快速交易的默认参数（利好则默认是现货买入，利空则默认是现货卖出）
  - 新闻分析报告
    - 猫咪分析：1-5句基本的观点和类型（绿色表示积极、红色表示消极），一个新闻的分析可以同时有积极的分析观点和消极的分析观点，

agent聊天的主要板块，也是当前目录内项目主要专注的地方（这里是想看看这里怎么做一个统筹agent）
- Agent context：
  - 用户当前所处的页面的上下文（pathname）
  - 用户最近7天的交易记录
  - 用户的最近7日总盈亏、各个持有代币盈亏情况
  - 用户最近7天标记喜欢/不感兴趣的新闻
  - 用户今天看过的所有新闻
- Agent prompt（角色认定）
  - 你是一只拟人化的宠物猫，你善于通过分析新闻和用户的交易情况，精准回答用户的问题
  - 用户的4d人格和用户画像、用户画像描述
- Agent 输入
  - 用户的文本输入（此阶段仅支持文本输入）
  - 用户的快捷指令（推荐问题、持仓快速分析按钮）
- Agent 输出
每一次对话，根据agent自己判断文本和动作的组合返回，并不是文本/动作二选一
  - 文本（message）：对用户的问题的精准回答
  - 动作（tools）：
    - 查询（文本）
      - 查询用户总的美元估值余额
      - 查询某个代币的资产余额
      - 查询某个代币相关的相关新闻、信息、价格走势（默认最近7日价格走势）
    - 资产分析（文本+md格式的表格）
      - 用户点击猫窝的“资产分析”进行分析时候，AI的回应涉及对用户当前现货持仓、合约持仓做分析，需要用表格形式呈现结构化的数据，本阶段采用的是markdown的表格渲染，或者AI后端返回的特殊json数据来做前端的表格渲染
      - 提供一些交易建议（本阶段暂不实现，具体可以根据大家用户体验反馈来优化）
    - 交易
      - 发起代币现货、合约交易前，AI如果检查到用户的USDC余额不足，则先文字提醒用户充值USDC，并给出按钮，用户点击可以跳转到“购买”
      - 交易某个代币现货（调起快速交易窗口，并根据不同的用户调整不同的预设参数）
      - 交易某个代币合约（调起快速交易窗口，并根据不同的用户调整不同的预设参数）
      - 交易时给出模拟交易结果的信息弹窗，并让用户确认（后续的Defi协议）
      - 批量调整仓位（Defi协议之间的资金挪转）
  - 聊天历史保存
    - 用户最近1天聊天内容作为短记忆
    - 用户最近30天聊天内容的摘要作为长记忆，compat
